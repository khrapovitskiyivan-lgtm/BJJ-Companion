# Стартовый набор новичка — дизайн

Дата: 2026-08-01
Статус: согласован (направление + правки пользователя), готов к плану реализации.

## Проблема

Новый белый пояс после онбординга не понимает «с чего начать». Стартовый экран «Моя игра» даёт одно микро-действие (`cold-start` — «Запиши тренировку»), а раздел Техники открывается графом `/map`, который для новичка «карта метро» (опрос 2026-07-22, п.25.4 и п.25.7; прямой запрос Александра, белый 2 мес — «дорожная карта» вместо графа). Обзорного «вот база, с которой начинают» в приложении нет.

## Назначение и рамка

Фича — **активация/ясность первого запуска**, НЕ рост охвата. Она не приносит новых пользователей и не сдвинет app_open/день. Настоящие рычаги охвата (виральность партнёров, шеринг, тренер, видео) — отдельно. Поэтому стартовый набор делается как **малая ставка**, без переинвестиций (без новой граф-подобной визуализации, без «режима новичка» на `/map`).

Назначение (вердикт независимого продуктового эксперта, развилка «постоянная карта / разовый разгон / оба»): **постоянная дорожная карта** (живёт, пока пользователь белый) + лёгкое промо новичку через уже существующую ленту инсайтов. Разовую самоисчезающую карточку не делаем: белый остаётся новичком 1-2 года, ориентир не должен пропадать, пока пользователь ещё путается.

## Решения пользователя (жёсткие)

1. Вкладка «Старт» — **первой** в ряду под-вкладок раздела Техники (перед «Карта»).
2. Вкладка доступна **только при белом поясе** (`profile.belt === "white"`). Синий и выше её не видят. Это сознательно переопределяет рекомендацию эксперта «доступна всем всегда» в пользу white-only.

Следствие: видимость вкладки гейтит сам пояс, отдельный порог по `doneCount` для показа вкладки не нужен. Порог остаётся только для приоритета промо-героя на «Моей игре».

## Что НЕ делаем (границы)

- НЕ курируем набор алгоритмически через `nextToLearn`/`isUnlocked`. Проверено по данным: у свежего белого пояса `isUnlocked` (все пререквизиты = done) истинно лишь для ~4 техник (254/340 в циклах пререквизитов). Breadth-first движок для этой аудитории вырождается и наполнять набор не может.
- НЕ добавляем 5-й таб в нижнюю навигацию. «Старт» — под-вкладка внутри раздела Техники; нижняя навигация остаётся 4 таба.
- НЕ вешаем постоянный блок на «Мою игру» (регресс консолидации `TodayAction`, п.24.C). Дискаверабилити новичку даёт переиспользованный инсайт-ряд.
- НЕ трогаем граф `/map` и порядок нижней навигации.
- НЕ меняем дефолтный роут раздела Техники (тап «Техники» в нижней навигации ведёт как раньше). См. открытый вопрос 1.

## Архитектура

Разбито на изолированные единицы с явными интерфейсами.

### 1. Данные набора — `data/starter-set.json`

Курированный список, паттерн `data/aliases.json` / `data/video-urls.json` (правит человек, не код).

Форма: массив тематических бакетов; бакет — заголовок RU + список id техник. Бакеты набора — СВОИ курируемые темы («Стойка и тейкдаун», «Гард снизу», «Проход гарда», «Выходы из-под контроля», «Базовые сабмишены», «Контроль сверху»), НЕ обязаны совпадать с `Group` enum (техника с `group=sweep` может стоять в бакете «Гард снизу»).

```
[
  { "title": "Стойка и тейкдаун", "ids": [<id>, ...] },
  { "title": "Гард снизу",        "ids": [<id>, ...] },
  ...
]
```

Объём: ~12-18 техник суммарно, отобранных из пула 79 белых техник с тегом `fundamental`. Конкретные id курирует персона `bjj-instructor` отдельным шагом плана (это data-курирование, не код). До курирования — временный минимальный набор для сборки/тестов.

Валидация в `scripts/build-data.mjs` (рядом с существующими валидаторами): каждый id существует в базе; техника имеет `belt === "white"` (предупреждение, не ошибка, если инструктор сознательно включит не-белую базовую); нет дублей id между бакетами. Ошибка валидации роняет билд, как для прочих данных.

### 2. Чистый модуль — `src/lib/bjj/starterSet.ts`

Единственная ответственность: дать структуру набора и посчитать прогресс. Не знает про React/DOM.

- `interface StarterBucket { title: string; ids: number[] }`
- `STARTER_SET: StarterBucket[]` — импорт из собранного JSON (через generated, как прочие данные).
- `interface StarterProgress { done: number; total: number; buckets: Array<{ title: string; total: number; done: number; techniques: Technique[] }> }`
- `starterProgress(progress: ProgressMap): StarterProgress` — по каждому бакету резолвит id в `Technique` (через `TECH_BY_ID`, пропуская несуществующие cycle-safe), считает `done` (`progress[id] === "done"`), агрегирует итог.

Тесты (`starterSet.test.ts`): пустой прогресс → done=0; частичный → корректные счётчики по бакетам и итог; несуществующий id в JSON не роняет (пропуск); итог = сумма бакетов.

### 3. Роут и вкладка — `src/routes/starter.tsx` + `src/components/bjj/StarterSet.tsx`

Роут `createFileRoute("/starter")` по образцу `library.tsx`: `<AppShell>` → `<PageHeader>` + `<TechniquesTabs/>` + `<StarterSet/>`.

Гейт пояса на уровне роута: `useProfile()`; после гидратации, если `profile.belt !== "white"` → `redirect`/`Navigate` на `/map` (обычный пользователь сюда не попадёт — вкладка скрыта; защита от прямого URL и от смены пояса, пока экран открыт). До гидратации — скелет/ничего (SSR-safe, как принято в проекте).

`StarterSet.tsx`:
- Прогресс-хедер: заголовок «С чего начать», подпись «Базовый набор белого пояса. Порядок — ориентир, а не строгий путь.», полоска `done/total` + «N из M».
- Бакеты: первые 1-2 раскрыты списком, остальные — свёрнутый аккордеон со счётчиком `done/total` (состояние раскрытия в локальном `useState`). Точное «сколько раскрыто по умолчанию» уточняется рантаймом по высоте (см. открытый вопрос 2).
- Строка техники — существующий `TechniqueRow` (маркер пояса слева, статус-иконка), тап → карточка `/technique/$id`. Отметка «изучено» происходит на карточке (существующий механизм статуса), НЕ инлайн — консистентно с остальным приложением и без нового UI отметки. Инлайн-цикл статуса (как `cycleStatus` в library) — отклонён ради консистентности и меньшего кода.
- Прогресс-хедер реактивно пересчитывается от `useProgress()`.

### 4. Ряд под-вкладок — `src/components/bjj/TechniquesTabs.tsx`

Добавить `useProfile()`. Первым элементом (перед «Карта») рендерить `<Tab to="/starter" label="Старт" .../>` ТОЛЬКО если `hydrated && profile.belt === "white"`. Иконка — `Flag` (lucide), тема «с чего начать».

Верстка: ряд `flex w-full`, табы `flex-1`. У белого станет 5 табов на ~380px (у остальных 4). При тесноте (самое длинное «Что если») — ужать `gap`/`px`/размер иконок в пределах компонента; фолбэк, если 5 не помещается читаемо, — убрать иконки у табов только когда виден «Старт». Проверяется рантаймом (скриншоты этого приложения таймаутят — через DOM/`getBoundingClientRect`).

### 5. Промо-инсайт — `src/lib/bjj/insights.ts`

Новый `InsightKind = "starter-set"`. Условие добавления в `computeInsights`:
- `belt === "white"`, И
- в наборе есть непройденное (`starterProgress(progress).done < total`).

Вес ~240 (выше `cold-start` 200 и `return-after-pause` 220), чтобы для нового белого стать героем дня вместо «Запиши тренировку». По мере отметок набор проходится → когда `done === total`, инсайт гаснет (хендофф на дневник, против истощения контента) и герой уступает `cold-start`/`plan`. Порог отсечки — прохождение набора, а не магическое число (проще и завязано на цель фичи).

- `reason`: «С чего начать: собери базу белого пояса».
- `route`: `/starter`. `techniqueIds: []`.
- `TodayAction`: добавить `starter-set` в мапу `CTA` («Открыть набор») и в `linkProps` (route `/starter`, не карточка техники).

Импорт `starterProgress` в `insights.ts` — чистый модуль на чистый модуль, без циклов.

### 6. Онбординг — `Onboarding.tsx`, `FinalScreen`

Если на онбординге выбран белый пояс — на финальном экране добавить вторичный CTA «Открыть стартовый набор» → `/starter` (первое касание сразу после онбординга). Дёшево, одна ссылка; при не-белом — не показывать.

### 7. Телеметрия

Событие `starter_open` (открытие вкладки; дедуп на сессию/сутки в `telemetry.ts` по образцу `section_open`). `reco_click` для промо-героя уже покрыт свободным `detail` по имени события — новый detail новой SQL не требует (урок п.31 г). Whitelist для `starter_open` — кумулятивный `create or replace bjj_track`, применяет пользователь инлайном в чат (память `feedback-sql-inline`).

## Поток данных / прогресс

Отметки набора — обычный статус `done` в существующем сторе (`useProgress`), без нового стейта. Синергия: `done` кормит `countDone`/`doneCount` → порог `ARCHETYPE_MIN_DONE=5` → разблокировка «Твой стиль» и промпта «Разрыв». Стартовый набор становится естественным способом перейти порог холодного старта. Пройденный набор = хендофф: промо гаснет, пользователь уходит в дневник/отработку.

## Edge-cases

- Прямой заход на `/starter` не-белым (URL) → редирект на `/map` (гейт роута).
- Смена пояса белый → синий, пока `/starter` открыт → пояс реактивен, гейт роута редиректит на `/map`; вкладка «Старт» исчезает из ряда. Отметки остаются в прогрессе.
- До гидратации `profile.belt` — не рендерить вкладку и не редиректить (ждать `hydrated`), иначе мигание/ложный редирект.
- Несуществующий id в `starter-set.json` — валидатор билда ловит; в рантайме `starterProgress` пропускает cycle-safe.

## Тестирование

- `starterSet.test.ts` (unit): прогресс по бакетам и итог, пропуск несуществующих id.
- `insights.test.ts` (+кейсы): `starter-set` появляется у белого с непройденным набором и вес делает его героем; исчезает при `done === total`; отсутствует у не-белого.
- `build-data.mjs`: прогон валидатора набора (id существуют, нет дублей).
- Рантайм через DOM (скриншоты таймаутят): вкладка «Старт» первой и только у белого; ряд табов не ломается по ширине; переход по строке на карточку; прогресс-хедер меняется при отметке; промо-герой на «Моей игре» у нового белого, гаснет при пройденном наборе.
