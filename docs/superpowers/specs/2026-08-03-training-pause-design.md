# Пауза тренировок (отсутствие: травма / отпуск / болезнь) — дизайн

Дата: 2026-08-03. Статус: дизайн на ревью владельца. Мотивация — реальный кейс: владелец травмировал ребро, не может тренироваться; сейчас приложение это НАКАЗЫВАЕТ (план «горит», бот шлёт «план под угрозой», серия рвётся, партнёры видят «отстаёт»).

## Проблема
Отсутствие по уважительной причине (травма, отпуск, больничный, работа) сейчас неотличимо от «забил». Механизмы подотчётности бьют по тому, кто и так в неприятной ситуации:
- недельный план начинает «гореть» (todayCard, `weekStatus.missed`);
- бот (tgRemind `decide`) шлёт вечерние «план под угрозой» и мягкие нуджи;
- серия недель (`planStreak`) рвётся на первой же пропущенной неделе;
- партнёры видят «отстаёт по плану».

Есть `/mute` (глушит ТОЛЬКО бота, план и серию в приложении не морозит) и реактивный инсайт `return-after-pause` (мягкая встреча при последней записи 14-90 дней назад). Не хватает ПРОАКТИВНОЙ управляемой паузы.

## Цель
Пользователь заранее говорит «меня не будет» → машина подотчётности ЗАМОРАЖИВАЕТСЯ без ощущения провала: план не горит, серия замирает (не рвётся), бот молчит, партнёры видят «на паузе», на возврате — мягкая встреча.

## Модель данных

Пауза хранится в профиле (синхронизируется в облако как остальной профиль). Нужна ИСТОРИЯ пауз, а не только «текущая»: `planStreak` пересчитывается из дневника каждый раз, поэтому чтобы серия не сломалась ПОСЛЕ снятия паузы, прошлые паузные недели должны оставаться известны.

```ts
// В StyleProfile (types.ts):
pauses?: PausePeriod[];   // история + активная; активная = та, где нет `to`

interface PausePeriod {
  from: string;   // ISO дата начала (yyyy-mm-dd)
  until?: string; // ISO планируемая дата возврата (опционально; для отпуска/больничного)
  to?: string;    // ISO дата фактического снятия; отсутствует => пауза АКТИВНА
}
```

- **Без срока (травма):** `{from, until: undefined, to: undefined}` — снимаешь руками.
- **С датой (отпуск):** `{from, until: "2026-08-20", to: undefined}` — авто-снятие по дате.
- **Снятие** (руками или авто по `until`): проставляется `to` = фактическая дата возврата.
- Активна максимум ОДНА пауза (у которой нет `to`). Новую поставить нельзя, пока активна текущая.

Чистые хелперы (`src/lib/bjj/pause.ts`, TDD):
- `activePause(pauses, today): PausePeriod | null` — активная пауза с учётом авто-снятия (если `until` задан и `today > until` — считается закрытой на `until`).
- `isPausedOn(dateKey, pauses, today): boolean` — попадает ли день в любой паузный интервал (закрытый `[from,to)` или активный `[from, effectiveEnd]`).
- `weekOverlapsPause(weekDays, pauses, today): boolean` — пересекает ли календарная неделя паузу.

## Поведение по поверхностям

### 1. Серия (planStreak) — ЗАМОРОЗКА, не сброс
Правило по каждой неделе (от текущей назад): квота добита (`weekDone >= quota`) → серия +1; иначе если неделя пересекает паузу → ПРОПУСК (нейтрально, не рвём, не считаем); иначе → стоп. `planStreak` принимает `pauses` и консультирует `weekOverlapsPause`. Так пауза серию никогда не рвёт, а если ты всё же добрал квоту на неделе с паузой — она засчитывается (бонус). `dayStreak` (без частоты): паузные дни не рвут — при возврате продолжаем (пропуск паузных дней в обходе).

### 2. «Сегодня» / «3 минуты» (todayCard) — спокойное состояние
`todayCardModel` принимает `pauses`. Если сегодня в активной паузе → новое состояние `paused: { until?: string }` вместо `week`. `TodayCard`: «На паузе» (+ «до DD.MM» если задано), кнопка «Снять паузу», БЕЗ дефицита и БЕЗ кнопки-нуджа «Записать». Мягкая вторичная строка «Захочешь — можно разобрать технику», без давления. `weekStatus.missed` для паузных недель = 0 (не горит).

### 3. Бот (tgRemind + cron + webhook) — молчит на паузе
- Новая колонка `paused_until date` в `bjj_tg_chats` (null = не на паузе; дата = пауза до неё включительно; без-срочная пауза = дальний сентинел, напр. `2099-12-31`).
- Клиент синхронизирует её: расширить существующий RPC `bjj_tg_report` параметром `p_paused_until` (отчёт плана уже уходит при открытии в Telegram — `tgReport.ts`). Плюс команды бота `/pause` и `/resume` (RPC `bjj_tg_set_pause`, паттерн `bjj_tg_set_muted`): `/pause` = без срока, `/resume` = очистить.
- `decide()`: в самом начале, если `row.paused_until` и `today <= paused_until` → `{kind:"none"}` (тишина — ни remind, ни soft, ни recap). Авто-снятие по дате бесплатно (когда `today > paused_until`, снова активен).
- `/pause` отвечает «Пауза. Вернёшься — встретим, поправляйся»; `/resume` — «С возвращением».
- `/mute` оставляем как есть (быстрый глушитель бота); пауза — отдельный честный статус (морозит и план, и серию, и партнёров).

### 4. Партнёры — «на паузе», не «отстаёт»
- `buildPublishInput` (partnersProfile.ts) + колонка в `bjj_partner_profiles`: `paused boolean` (+опц. `paused_until`). Публикуется вместе с профилем (reportPartnerProfile из AppShell).
- Карточка/строка партнёра: бейдж «на паузе» вместо недельного статуса. Из сортировки «отстающие сверху» паузных исключаем (не выставляем неудачником). Дневник/заметки как и раньше не видны.

### 5. Где ставить (UI)
- Дом — **лист игрока (CharacterSheet)**, секция «Пауза» рядом с частотой/днями (та же зона «как я тренируюсь»): кнопка «Поставить на паузу» + опциональная дата «до». Активна → «На паузе с DD.MM (до DD.MM)» + «Снять».
- Бот: `/pause` / `/resume`.
- (Фаза 4, позже) контекстная кнопка «Не можешь сейчас? Поставь паузу» в момент, когда план начинает гореть.

### 6. Возврат — мягкий
Дата `until` прошла или сняли руками → активная пауза финализируется (`to` проставляется при следующем открытии). Показать «С возвращением» + лёгкий старт (повтори знакомое, запиши первую после паузы) — переиспользуем существующий инсайт `return-after-pause` (расширить триггером «только что вышел из паузы», не только «14-90 дней молчания»).

## Разрешённые граничные случаи
1. **Пауза в середине недели:** неделя пересекает паузу → в `planStreak` пропускается (не рвёт), ЕСЛИ квота не добита; если добил до паузы — засчитывается. Недобор такой недели не «горит».
2. **Авто-снятие по дате:** `until` в прошлом → пауза считается закрытой на `until` во всех чистых хелперах; клиент финализирует `to` при следующем заходе; бот сам оживает, когда `today > paused_until`.
3. **Частично выполненная неделя при постановке паузы:** покрыто правилом (1) — засчитывается при добитой квоте, иначе нейтрально.
4. **Причина отсутствия:** НЕ спрашиваем (или необязательный лейбл), влияет ТОЛЬКО на тон копирайта. Никаких медсоветов «что тренировать с травмой» — вне нашей зоны, максимум «береги себя».
5. **Пауза + уже был `/mute`:** независимы; снятие паузы НЕ снимает mute (разные намерения).
6. **Открытая (без-срочная) пауза и `planStreak` глубоко назад:** активный интервал `[from, today]`; предохранитель обхода недель (520) уже есть.

## Стадии
- **Фаза 1 (ядро, клиент):** поле `pauses` + `pause.ts` хелперы (TDD) + заморозка в `planStreak`/`dayStreak`/`weekStatus`/`todayCardModel` + UI паузы в CharacterSheet + мягкий возврат. Чисто клиент, БЕЗ SQL — чинит опыт В приложении сразу, деплоится быстро.
- **Фаза 2 (бот молчит):** SQL `paused_until` в bjj_tg_chats + `bjj_tg_report`(+param)/`bjj_tg_set_pause` + `decide` тишина + `/pause` `/resume`. Останавливает DM-напоминания.
- **Фаза 3 (партнёры):** SQL `paused` в bjj_partner_profiles + publish + бейдж «на паузе» + сортировка.
- **Фаза 4 (полировка, опц.):** контекстная кнопка при «плане горит»; лейбл причины.

MVP для реального кейса владельца = Фаза 1 + Фаза 2 (в приложении спокойно + бот молчит). Фазы независимы и деплоятся по очереди.

## Тестирование
- `pause.ts`: activePause (без срока / с until в прошлом-будущем), isPausedOn (границы интервала), weekOverlapsPause. Юнит, даты параметром.
- `planStreak`/`dayStreak`: паузная неделя не рвёт серию; добитая квота на паузной неделе засчитывается; несколько пауз в истории.
- `todayCardModel`: paused-состояние вместо week; not-paused без регресса.
- `decide()`: paused_until в будущем → none на все ветки (remind/soft/recap); в прошлом → обычная логика. +существующие 16 тестов зелёные.
- Рантайм (DOM, скрины таймаутят): лист игрока — поставить/снять паузу; «Сегодня» показывает «На паузе»; обе темы.
