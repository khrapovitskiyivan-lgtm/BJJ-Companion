# Спека: Коронка + личный слой графа

Дата: 2026-07-30
Статус: черновик на ревью пользователя
Автор процесса: brainstorming (Spec-First v2)

## Контекст и проблема

Аудит связки персонализации (goal / style / рекомендации / отработка) показал: у приложения
есть сильное сырьё (граф 340 техник + дневник), но большинство поверхностей его не читают
и работают «на всех одинаково». Стратегический вывод (продукт + рынок): дифференциатор это
не «персонализация вообще» (её заявляют все, включая AI-native конкурентов), а **персонализация,
завязанная на наш граф + твой дневник** которую заметочник-конкурент скопировать не может.

Две конкретные дыры, которые закрывает эта спека:

1. **Нет сигнала персонализации на уровне техники.** Есть `goal` (зачем тренируюсь),
   `preferredStyles` (как хочу играть, архетип), прогресс (выучил/нет). Но ничего про
   «мои коронные приёмы» конкретные техники, на которые я ставлю. «Избранное» сейчас
   пассивная закладка (иконка-звезда, счётчик + список), без смысла и без роли в логике.

2. **Граф не читается как ЛИЧНАЯ карта.** Статус прогресса на узле уже есть, но сигнал
   слабый (точка 8px). Рекомендация используется только как точка входа (граф открывается
   на «следующей цели»), постоянной метки на узле нет. Избранного/коронок в графе нет вовсе.

Иерархия персонализации, в которую всё вкладывается без противоречий (ответ на исходный
запрос «чтобы работало как часы»):

> `goal` (зачем) -> `preferredStyles` (как играю) -> **коронки** (мои оружия) -> прогресс (освоил)

## Решения пользователя (зафиксированы)

- Коронка = **вариант A**: «приём, на который ты ставишь» (коронный/надёжный приём).
  НЕ «вишлист, хочу выучить потом» (это покрывается статусом «в процессе»).
- Порядок: **коронка + граф первым** заходом. Связный генератор вокруг коронок это
  следующая спека.
- Раннер-таймер отработки оставляем как есть (телеметрии `workout_run=0` пока недостаточно
  для решения о демоуте).

## Область (этой спеки)

**В область входит:**

1. Ребрендинг «избранное» -> «коронка» на всех пользовательских поверхностях
   (иконка звезда -> корона, копия). Смысл = вариант A.
2. Личный слой на графе `/map`:
   - (a) статус прогресса читаемый (не только 8px точка);
   - (b) постоянная метка «Следующее» на узле-рекомендации;
   - (c) корона на узлах-коронках.

**Вне области (отдельные будущие спеки, перечислены для ясности границ):**

- Связный генератор отработки вокруг коронок и их `chain_to`/контров (коронка как ВХОД
  генератора). Здесь коронка только вводится и отражается, но логику подбора НЕ меняет.
- Карточка-тренер (персональные секции вместо общих «Похожих»).
- Дешёвые семена: засеять `preferredStyles`, сделать `goal` редактируемым.
- Фиксы #2 (мёртвый фильтр безопасности) и #3 (мёртвые поля «качеств») делаем отдельно
  вместе со связным генератором, не здесь.

## Модель данных (без изменений схемы)

Коронка ЭТО текущее множество избранного, просто переименованное в UI. Переиспользуем
существующий `useFavorites` без миграций:

- Ключ localStorage `bjj.favorites.v1` НЕ меняется.
- Облачная колонка `favorites_data` (jsonb в bjj_progress) НЕ меняется.
- Событие телеметрии `favorite_toggle` НЕ меняется (внутренняя метка; переименование
  потребовало бы правки whitelist в SQL и дало бы разрыв истории событий).
- Хук `useFavorites`, тип `FavoritesMap`, `StatListKind="favorites"`, `openList="favorites"`
  внутренние идентификаторы, НЕ меняются.

Правило: **меняется только пользовательская копия и иконка.** Любой рефактор внутренних
имён вне области спеки.

Определение смысла доносится микрокопией в UI (подсказка у контрола коронки), чтобы «коронка»
читалась как «на что ты ставишь», а не «закладка».

### Личный слой графа

- `src/components/bjj/flow/TechniqueNode.tsx`
  - Тип `TechNode` data += `crown?: boolean`, `recommended?: boolean`.
  - **Статус читаемый:** фон узла получает мягкий тон по статусу (color-mix со статус-цветом,
    низкая альфа), поверх существующего `--color-card`. Точка+подпись статуса остаются.
    Обе темы. Not_started остаётся дефолтным фоном (без тона).
  - **Корона:** иконка `Crown` (золото `--brand-gold-ink`) в правом верхнем углу узла,
    когда `data.crown`. Внутри границ узла 156px, не влияет на раскладку.
  - **Метка рекомендации:** маленькая пилюля «Следующее» (primary) в верхней части узла,
    когда `data.recommended`. Отличается от кольца `selected` (это «в фокусе», не «рекомендовано»):
    кольцо остаётся у фокуса, пилюля у рекомендации. Если узел одновременно рекомендация и
    коронка обе метки помещаются (пилюля слева, корона справа).
  - Метки не перекрывают кнопку «Открыть» (она появляется только у `selected` ниже контента).
- `src/components/bjj/flow/TechniqueFlow.tsx`
  - Импорт `useFavorites`.
  - Выделить `recommendedId` в memo (сейчас рекомендация считается только для `startId`;
    та же `nextToLearn(...)[0]?.id ?? currentFocus(...)?.id`).
  - В эффекте влива данных (сейчас статус+`selected`) добавить в data узлов:
    `crown: !!favorites[id]`, `recommended: id === recommendedId`.
  - Зависимости эффекта += `favorites`, `recommendedId`.

### Ограничение по природе графа (зафиксировать, не баг)

Граф `/map` это ЛОКАЛЬНАЯ окрестность одной техники в фокусе (зональная раскладка:
setup_from сверху, chain_to снизу, альтернативы слева), а не всё дерево 340 узлов.
Значит метки (корона / рекомендация) появляются только на **отрисованных сейчас** узлах.
Коронка вне текущей окрестности покажет корону, когда до неё дойдёшь навигацией/поиском.
Быстрый переход «к моим коронкам» вне области этой спеки (поиск техники уже есть).

## Согласованность (почему без новых противоречий)

Эта спека НЕ трогает логику подбора (`recommend.ts`, `workout.ts`). Коронка вводится как
пользовательский сигнал и отражается визуально, но ни в `nextToLearn`, ни в генераторы не
входит здесь. Значит новых расхождений в рекомендациях не появляется. Подключение коронки как
входа с явным прецедентом (`goal -> style -> коронка -> прогресс`) отдельная следующая спека.

## Тестирование и верификация

- **Юнит (vitest):** если выделяем хелпер выбора `recommendedId`, покрыть тривиальным тестом;
  основная логика рекомендации уже покрыта `recommend.test.ts`. Ребрендинг копии тестами не
  покрывается (строки).
- **Рантайм через DOM (обязательно):** скриншоты превью графа стабильно таймаутят (известный
  грабль), проверяем через `javascript_tool`:
  - корона появляется на узле, отмеченном коронкой; исчезает при снятии;
  - пилюля «Следующее» на узле-рекомендации (id == `recommendedId`);
  - фон узла тонирован по статусу (done/in_progress/not_started) в обеих темах;
  - попарный детектор пересечений `getBoundingClientRect` по узлам проходит (метки внутри
    границ узла, раскладка не поехала).
- **Карточка/шапка:** корона в шапке карточки техники и лейбл «Коронки» в «Моей игре»
  отражаются реактивно (тап по короне -> появление в списке «Твои коронки»).
- **Сборка:** `npx vitest run` зелёный, `node scripts/build-data.mjs` не требуется (данные
  техник не меняются).

## Риски

- Скриншоты графа таймаутят -> только DOM-проверка (учтено выше).
- Соблазн переименовать внутренние идентификаторы избранного -> сломает облако/телеметрию;
  спека явно запрещает (только копия+иконка).
- Метки на узле не должны переполнять 156px или наезжать на кнопку «Открыть» у фокуса.
- Тон статуса не должен конфликтовать с левой цветной границей пояса (4px) и точкой группы
  проверить читаемость в обеих темах.

## Критерий готовности

- Звезда заменена короной везде в пользовательском UI; смысл «на что ставишь» донесён копией.
- На графе: статус читаем, узел-рекомендация помечен, коронки помечены короной обе темы,
  подтверждено DOM-проверкой.
- Внутренние идентификаторы, облачная синхронизация и телеметрия не тронуты.
- Логика подбора рекомендаций/отработки не изменена (нулевой риск новых противоречий).
- Тесты и сборка зелёные.
