# Спека: Карточка-тренер (персонализация карточки техники)

Дата: 2026-07-31
Статус: черновик на ревью пользователя
Процесс: brainstorming (Spec-First v2). Step 3 дорожной карты
`docs/analysis/2026-07-30-personalization-roadmap.md`.

Форма подтверждена двумя независимыми экспертами (UX/ИА + продукт), сошедшимися на
гибриде ближе к «лёгкому» варианту.

## Контекст и проблема

Карточка техники (`src/routes/technique.$id.tsx`) — самая частая поверхность приложения,
но безлична: общий блок «Похожие техники» (срез group+belt, 0% персонализации) и 5 списков
связей (`RelatedList`) = просто резолв id. Карточка УЖЕ длинная (~15-17 блоков). Step 3
делает её персональной, НЕ раздувая.

Ключевой факт (нашли эксперты): списки «Заходы из» (`setup_from`) и «Продолжения» (`chain_to`)
СВЁРНУТЫ по умолчанию (`RelatedList defaultOpen` только у «Что изучить сначала»). Значит наивное
«встроить метки внутрь списков» прячет сигнал за тап. Против чистого «выделенного блока» — тоже
оба эксперта: карточка длинная (safety-блок риска нельзя оттеснять), блок дублирует нарратив
«Разрыва» с «Моей игры», и «зачем тебе это» у большинства сейчас деградирует (стиль не засеян,
дыра требует 2+ поимок) — большая сцена под пустой сигнал = слабое первое впечатление.

## Решения (зафиксированы)

Гибрид ближе к «лёгкому»:
1. **«Зачем тебе это»** — одна строка ВНУТРИ шапки (после описания), primary-акцент + иконка
   (НЕ золото — золото зарезервировано за достижениями). Показывается ТОЛЬКО при сильной причине;
   при пустых данных — НЕ показываем (никакого generic-филлера).
2. **«Твой следующий шаг»** — видимая строка-ссылка «Дальше: X ->» сразу под шапкой (НЕ бейдж
   внутри свёрнутого списка) + подсветка того же пункта в «Продолжениях» при раскрытии.
3. **«Знаешь N из M»** — в всегда видимой summary-пилюле списков «Что изучить сначала» (prereq)
   и «Заходы из» (setup_from): вместо числа `{items.length}` -> `{done}/{total}`.
4. **Убрать «Похожие техники»** (0% персонализации, чистая замена).
5. **Телеметрия** — клики через существующий `reco_click` с detail (`next_step`/`why`) — БЕЗ новой
   SQL (whitelist по имени, detail свободный); плюс событие показа `coach_shown` (детализация
   причины) для знаменателя — 1 малая SQL-миграция.

## Область

**В область:** новый чистый модуль `coachCard.ts`; строка причины в шапке; строка «следующий
шаг»; N/M-пилюли у prereq/setup_from; подсветка next-step в chain_to; удаление «Похожие»;
телеметрия. Только `setup_from` / `chain_to` / `prerequisites` (роадмап называет их).
**Вне области:** `common_setups`/`usedBy` (не трогаем); выделенный блок «Тренер» (отклонён);
изменение логики генератора step 2.

## Иерархия сигналов и зрелость данных (важно)

У трёх сигналов РАЗНАЯ зрелость — трактовка видимости разная:
- **N из M** — счётчик, всегда корректен, персонализации не требует. Всегда видим (пилюля).
- **Следующий шаг** — деградирует изящно: без стиля/цели просто сортирует chain_to по сложности
  (осмысленный дефолт). Показываем всегда, если есть непройденный chain_to.
- **«Зачем тебе это»** — единственный, что при пустых данных даёт скучный фолбэк. Поэтому
  `cardReason` возвращает `null`, когда нет СИЛЬНОЙ причины, и строку НЕ рисуем (не филлер).

Приоритет причины (`cardReason`): дыра (техника защищает от того, чем ловят) > стиль (техника в
твоём effective-стиле) > цель (очковая под соревнования). Иначе `null`.

## Архитектура

Новый чистый модуль `src/lib/bjj/coachCard.ts` (SSR-safe, всё параметрами). Переиспользует
`effectiveStyleSet`/`goalScore` (уже есть) и `topCatchers` (`caught.ts`).

### Контракты

```ts
import type { Belt, DiaryEntry, Goal, Style, Technique } from "./types";
import type { ProgressMap } from "./store";

// «Знаешь N из M»: сколько из переданных id освоено
export function knownCount(ids: number[], progress: ProgressMap): { done: number; total: number };

// Лучшее следующее звено из chain_to: непройденное, ранг стиль -> goalScore -> сложность -> id.
// null, если непройденных продолжений нет.
export function nextStep(input: {
  tech: Technique; byId: Map<number, Technique>; progress: ProgressMap;
  styleSet: Set<Style>; goal?: Goal; gi?: boolean; noGi?: boolean;
}): Technique | null;

// «Зачем тебе это»: сильная причина или null (без филлера). Приоритет дыра > стиль > цель.
export function cardReason(input: {
  tech: Technique; entries: DiaryEntry[]; styleSet: Set<Style>;
  goal?: Goal; gi?: boolean; noGi?: boolean; byId: Map<number, Technique>;
}): { kind: "gap" | "style" | "goal"; text: string } | null;
```

Логика:
- `knownCount`: `{ done: ids.filter(id => progress[id]==="done").length, total: ids.length }`.
- `nextStep`: кандидаты = `tech.chain_to` -> byId -> есть и `progress!=="done"`; сорт
  `(в styleSet?1:0) desc || goalScore desc || difficulty asc || id asc`; вернуть первый.
- `cardReason`:
  - дыра: для `topCatchers(entries, 3)` если `catcher.id` в `tech.setup_from` ->
    `{ kind:"gap", text:"Закрывает твою дыру: " + byId.get(catcher).nameRu }`.
  - стиль: `tech.styles.some(s => styleSet.has(s))` -> `{ kind:"style", text:"Усиливает твою игру" }`.
  - цель: `goal==="competition" && tech.points_ibjjf>0` -> `{ kind:"goal", text:"Очковая под соревнования" }`.
  - иначе `null`.

### RelatedList (`src/components/bjj/technique/RelatedList.tsx`)
- +проп `badge?: React.ReactNode` — если задан, рендерится вместо счётчика `{items.length}` в
  summary (для «N/M»).
- +проп `highlightId?: number` — если элемент списка == highlightId, подсветить строку
  (тонкая рамка/фон primary у `<li>`) — для «твой следующий шаг» в «Продолжениях».

### technique.$id.tsx
- Добавить `useDiary` (нужны entries для дыры) и `hydrated`-флаги (`useProgress`/`useProfile`/
  `useDiary`), `practiceCount`. Вычислить `styleSet = effectiveStyleSet(profile, progress,
  practiceCount)`, `byId = TECH_BY_ID`-мапа, `reason = cardReason(...)`, `step = nextStep(...)`.
- **Гейт гидратации:** персональные добавки (reason, step, N/M) рендерятся только когда все три
  стора гидратированы — иначе прыжок layout на самом заметном месте (как `mounted`-гейт в GapCard).
  До гидратации: пилюли показывают обычное число, строк reason/step нет.
- **Шапка:** после `concept` (внутри контейнера шапки) — строка причины при `reason` (иконка
  Compass + `reason.text`, primary-тон).
- **Под шапкой:** строка «Дальше: {step.nameRu} ->» (Link на `/technique/$step.id`) при `step`.
  На клик — `track("reco_click", "next_step")`. Клик по строке причины (если ведёт куда-то) —
  `reco_click`/`why` (или просто трек показа, см. ниже).
- **RelatedList «Что изучить сначала» (prereq)** и **«Заходы из» (setup_from)**:
  `badge={`${knownCount(ids, progress).done}/${...total}`}` (только когда total>0 и гидратировано).
- **RelatedList «Продолжения» (chain_to)**: `highlightId={step?.id}`.
- **Удалить** секцию «Похожие техники» (и вычисление `similar`).
- **Показ:** при гидратации, если есть хотя бы reason/step -> `track("coach_shown", reason?.kind
  ?? "next", { dailyDedup: true })`.

### Телеметрия
- `reco_click` — расширяем detail (`next_step`, `why`), новой SQL НЕ нужно.
- `coach_shown` — новое событие в union `telemetry.ts`; whitelist
  `docs/sql/2026-07-31-telemetry-coach-shown.sql` (полный whitelist + `coach_shown`).

## Тестирование

- **Юнит (vitest)** `coachCard.test.ts` на синтетических техниках:
  - `knownCount`: done/total считается верно; total=0 -> {0,0}.
  - `nextStep`: пройденные chain_to исключаются; ранг стиль>goal>сложность; пусто -> null;
    без стиля/цели деградирует к сортировке по сложности.
  - `cardReason`: дыра бьёт стиль бьёт цель; нет сильной причины -> null (не филлер);
    competition+points -> goal; стиль-совпадение -> style.
- **Рантайм через DOM** (превью `bjj-companion`; это карточка-список, скриншоты работают):
  - N/M в summary-пилюле «Что изучить сначала»/«Заходы из» видно БЕЗ раскрытия;
  - строка «Дальше: X» под шапкой; клик ведёт на технику;
  - строка причины при сильной причине; при пустых данных строки НЕТ;
  - «Похожие» отсутствует; обе темы; нет прыжка layout (гейт гидратации).
- **Сборка:** `npx vitest run` зелёный; данные техник не трогаются.

## Риски

- **Свёрнутые аккордеоны** прячут сигнал -> N/M в summary (видна всегда) + «следующий шаг»
  отдельной видимой строкой (не внутри списка). Снято дизайном.
- **Зрелость данных** -> `cardReason` возвращает null без сильной причины (не показываем филлер);
  next-step и N/M деградируют изящно.
- **SSR/гидрация** -> гейт по hydrated (иначе прыжок layout на видном месте).
- **Общие компоненты** (`TechniqueRow`/`RelatedList`) — только аддитивные пропы (`badge`,
  `highlightId`), не ломаем прочих потребителей `TechniqueRow` (у него уже есть слот `right`).
- **Измеримость** -> `coach_shown` (знаменатель) + `reco_click` detail (клики), иначе слепота
  как с раннером (`workout_run=0`).

## Критерий готовности

- Карточка техники персональна: причина (при сильном сигнале), следующий шаг видимой строкой,
  N/M в пилюлях; «Похожие» удалена. Логику генератора не трогаем.
- `cardReason` без сильной причины ничего не рисует (не филлер).
- Телеметрия `coach_shown` + `reco_click` detail; SQL подготовлен.
- Тесты и сборка зелёные; рантайм подтверждён через DOM в обеих темах, без прыжка layout.
