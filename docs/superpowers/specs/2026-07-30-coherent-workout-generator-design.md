# Спека: Связный генератор отработки (якорный позиционный кластер)

Дата: 2026-07-30
Статус: черновик на ревью пользователя
Процесс: brainstorming (Spec-First v2). Step 2 дорожной карты
`docs/analysis/2026-07-30-personalization-roadmap.md`.

Дизайн подтверждён оценкой двух независимых профильных агентов (инструктор БЖЖ по методике +
продакт по спорт/habit-трекерам), сошедшихся на варианте C = якорный позиционный кластер.

## Контекст и проблема

Текущий генератор (`src/lib/bjj/workout.ts`) выдаёт плоский список из N НЕсвязанных техник
по равному времени (round-robin по группам). Он:
- не использует граф переходов (`chain_to` не обходится вовсе; `setup_from` только как
  буст защит в дневниковом режиме);
- не использует стиль игрока (`preferredStyles`) и избранное (`favorites`);
- персонализируется мёртвыми полями `flexibility/pressure/long_limbs/speed` (нигде не
  проставляются -> ветка всегда пустая, фикс #3);
- «Безопасный» режим не режет опасное: `CRITICAL_TAGS` = 0 совпадений в базе (фикс #2).

Методически это фрагментация без глубины и переноса. Дифференциатор (граф+дневник) невидим.
Факт телеметрии: `workout_run = 0` (раннер-таймер никто не запускал, выборка мала) -> выход
генератора потребляется как СПИСОК-ЧТЕНИЕ, не как ведёная тайм-сессия. Значит выигрыш должен
идти от легибельности списка (связность видна как текст), а не от тяжёлой сессионной механики.

## Решения пользователя (зафиксированы)

- Форма сессии = **C, якорный позиционный кластер** (не голая линия A, не список B):
  `вход -> приём -> 1-2 продолжения + родственники из той же позиции`, поданный как
  легибельный заголовок темы над взвешенным списком.
- В область входят пререквизиты, без которых форма бессмысленна: effective-style-фолбэк
  (#1), фикс #2 (безопасность), фикс #3 (мёртвые качества), телеметрия темы.
- ВНЕ области (отдельно, позже): соло/партнёр-разметка дриллов; `goal` редактируемым (#4).

## Иерархия сигналов (ядро — «работает как часы», без противоречий)

> прогресс/дневник (гейт) -> **избранное** (выбор якоря) -> **стиль** (вес) -> **goal** (мягкий нудж + крен на безопасность)

- **Прогресс/дневник = жёсткий гейт кандидатов.** Якорь обязан быть тем, что человек реально
  ведёт: избранное / «в процессе» / свежий дневник. Плюс пояс/формат/безопасность (`available`).
- **Избранное = выбор якоря.** Сильнейший явный сигнал «моя игра», старший среди мягких.
- **Стиль = взвешивание** (тай-брейк среди кандидатов-якорей и среди родственников-добора),
  НЕ фильтр.
- **goal = мягкий нудж** (существующий `goalScore`), самый лёгкий вес; работает как крен на
  безопасность (health -> вниз критичное; competition -> вверх очковое; self-defense -> выходы/тейкдауны).
- **ПРАВИЛО ДОВЕРИЯ (инвариант):** goal и стиль НИКОГДА молча не выкидывают технику, которую
  пользователь сам занёс в избранное. Они меняют ПОРЯДОК и ВЕС, но не удаляют явный выбор.
  goal может лишь КРЕНИТЬ на безопасность (кап веса критичного), не банить избранный якорь.
- **Разрешение конфликта:** при расхождении предпочитать самое ЯВНОЕ и самое СВЕЖЕЕ действие
  (избранное/«в процессе» бьёт выведенный стиль; свежий дневник бьёт старое избранное) -
  гасит «скачущие рекомендации».

## Область (этой спеки)

**В область входит:**
1. Новый чистый модуль подбора кластера + рефактор обоих генераторов на него.
2. Выбор якоря по иерархии сигналов; ротация якоря (свежесть дневника + не повторять якорь
   прошлой сессии).
3. Сборка упорядоченного кластера из графа (вход -> якорь -> продолжения -> родня), cycle-safe.
4. Время по новизне (замена равного времени).
5. Effective style = `preferredStyles` ?? выведенный topStyle (#1 действует у всех).
6. Фикс #2: критичность по `injuryRisk «КРИТИЧНО»`/`leg_locks`/`spinal_lock`.
7. Фикс #3: убрать мёртвую ветку качеств; удалить 4 устаревших поля `StyleProfile`.
8. UI: заголовок темы (якорь + «почему») над кластером; телеметрия темы.

**Вне области:** соло/партнёр-разметка; `goal`-editable; карточка-тренер (step 3); онбординг
шаг стиля (эффект даёт effective-style-фолбэк без нового экрана).

## Архитектура

Новый чистый модуль `src/lib/bjj/workoutCluster.ts` (SSR-safe, без сторов; всё параметрами -
тестируемость). `workout.ts` вызывает его вместо текущего «отсортировать available и срезать».
`availableFor` / `splitTime` / `assemble` переиспользуются.

### Контракты (сигнатуры)

```ts
// effective style: заданный игроком приоритетнее выведенного из активности
export function effectiveStyleSet(
  profile: StyleProfile, progress: ProgressMap, practiceCount: Record<number, number>,
): Set<Style>; // preferredStyles если непусто, иначе {топ computeStyleAffinity}, иначе пусто

// критичность техники для фикса безопасности (заменяет мёртвый CRITICAL_TAGS)
export function isCriticalTech(t: Technique): boolean; // injuryRisk «КРИТИЧНО» || tags leg_locks/spinal_lock

// выбор якоря: пул = available ∩ (favorites ∪ in_progress ∪ свежий дневник)
export function pickAnchor(input: {
  available: Technique[]; favorites: FavoritesMap; progress: ProgressMap;
  entries: DiaryEntry[]; styleSet: Set<Style>; goal?: Goal; gi?: boolean; noGi?: boolean;
  avoidId?: number; // якорь прошлой сессии (ротация)
}): Technique | null; // null -> холодный старт (фундамент по поясу решает вызывающий)

// сборка упорядоченного кластера вокруг якоря; всё из available; cycle-safe, кап длины
export function buildCluster(input: {
  anchor: Technique; available: Technique[]; styleSet: Set<Style>;
  goal?: Goal; gi?: boolean; noGi?: boolean; progress: ProgressMap; count: number;
}): Technique[]; // [вход?, якорь, ...продолжения(1-2), ...родня] длиной <= count, порядок фикс.

// причина темы для заголовка
export function themeReason(
  anchor: Technique, favorites: FavoritesMap, progress: ProgressMap, entries: DiaryEntry[],
): string;
```

### Алгоритм

**1. Кандидатный пул якоря** = `available` ∩ (`favorites` ∪ status==in_progress ∪ техники из
записей дневника за последние 21 день). Пусто -> вернуть null.

**2. Ранг кандидатов** (по убыванию): избранное (+база) > in_progress > свежесть дневника;
далее вес стиля (пересечение `t.styles` со `styleSet`); далее `goalScore` (мягкий, как есть).
Исключить `avoidId`. Верхний = якорь. Пусто/null -> вызывающий берёт фундаментальную позицию
по поясу (первый `available` группы position/fundamentals, стиль решает ничьи).

**3. Кластер вокруг якоря** (все шаги строго из `available`, `visited`-guard, общий кап длины):
- **вход:** 1 из `anchor.setup_from` ∩ available (предпочесть позицию/проход; вес стиля при ничьих);
- **якорь;**
- **продолжения:** 1-2 из `anchor.chain_to` ∩ available, отранжированные стилем/целью;
- **родня (добор до count):** техники той же `group`, что якорь, делящие с якорем хотя бы один
  `setup_from` id (та же точка входа = альтернативы из той же позиции), отранжированные
  стилем/целью; НЕ случайные.
- Порядок в выдаче фиксирован: вход -> якорь -> продолжения -> родня. Никогда не выдавать
  «поток» из 1 узла (если ветки отсеклись — добирать родню; если и родни нет — обычный
  взвешенный добор по `available`).

**4. Время по новизне** (замена равного `timePerDrill`): не начатым / мало-отработанным больше
минут, знакомому якорю / часто-отработанному меньше. Сумма = `mainMinutes` (перераспределение,
не изменение общей длительности). Минимум 2 мин на технику (как сейчас).

**5. Оба генератора** (`generateWorkout` профиль / `generateWorkoutFromDiary` дневник)
переводятся на `pickAnchor` + `buildCluster`. Разница источников сохраняется только в РАНГЕ
якоря: дневниковый сильнее весит свежесть/`caughtBy`-защиты, профильный — избранное/in_progress.
Дневник пуст -> кластер строится по избранному/in_progress; совсем пусто -> холодный старт.

**6. Фикс #2 (безопасность).** `safetyOk` в `workout.ts`: критичность считать `isCriticalTech`
(injuryRisk «КРИТИЧНО» / leg_locks / spinal_lock), а не по пустому `CRITICAL_TAGS`. Режим
«Безопасный» реально режет опасное; «Умный» — для white/blue. Кластер строится ИЗ `available`
(пост-фильтр), поэтому цепочка никогда не покажет залоченный/критичный узел новичку.

**7. Фикс #3.** Убрать из `generateWorkout` ветку `preferred` из `flexibility/pressure/
long_limbs/speed`. Удалить эти 4 поля из `StyleProfile` (используются только здесь; в сторах
не проставляются — старые профили с этими ключами читаются без ошибок, лишние поля игнорируются).

## Данные / типы

- `Workout` += `theme?: { anchorId: number; reason: string }` (для заголовка; необязательно,
  чтобы пустой результат/холодный старт не падал).
- `StyleProfile`: удалить `flexibility?`, `pressure?`, `long_limbs?`, `speed?`.
- Данные техник не меняются (`build-data.mjs` не нужен).

## UI (маршрут отработки `src/routes/workout.tsx`)

- Над списком-планом — **заголовок темы**: имя якоря (`theme.anchorId` -> `TECH_BY_ID`) +
  строка «почему» (`theme.reason`). Приоритет причин (`themeReason`): избранное («Твой
  избранный приём») -> in_progress («Ты это учишь») -> свежий дневник («Свежее с тренировки»)
  -> закрывает дыру (защита от topCatcher: «Закрывает твою дыру: <ловец>») -> холодный старт
  («Основа под твой пояс»).
- Кластер рендерится текущими карточками, но В ПОРЯДКЕ выдачи (вход -> якорь -> продолжения
  -> родня). Ручки конфига и плитки источника «По профилю/По дневнику» остаются.
- Телеметрия: новое событие `workout_theme` (detail = anchorId) при показе плана с темой
  (дедуп в рамках генерации, как `workout_filter`). Whitelist: `docs/sql/2026-07-30-telemetry-
  workout-theme.sql` (применяет пользователь). До применения SQL событие глотается catch
  (как было с прочими до их SQL).

## Тестирование

- **Юнит (vitest, синтетические техники — id вне базы, как в существующих тестах):**
  - `effectiveStyleSet`: preferredStyles приоритетнее выведенного; пустой -> выведенный топ;
    нет активности -> пустой.
  - `isCriticalTech`: ловит injuryRisk «КРИТИЧНО» и теги leg_locks/spinal_lock; не ловит обычные.
  - `pickAnchor`: избранное бьёт in_progress бьёт свежий дневник; `avoidId` исключается;
    пустой пул -> null; правило доверия (goal=health НЕ выкидывает избранный хилхук-якорь,
    но кренит вес).
  - `buildCluster`: порядок вход->якорь->продолжения->родня; всё из available; cycle-safe
    (цикличный граф не зависает, кап работает); тонкий якорь (нет chain_to) -> добор родни,
    не «поток из 1»; родня делит setup_from с якорем.
  - время-по-новизне: сумма = mainMinutes, минимум 2, новому больше знакомого.
  - Оба генератора: не падают на пустом дневнике/пустом избранном (холодный старт).
- **Рантайм через DOM** (превью `bjj-companion`, порт 8080): заголовок темы + упорядоченный
  кластер на обоих источниках; смена фильтров пересобирает; обе темы. Скриншоты списка ок
  (это не граф).
- **Сборка/валидатор:** `npx vitest run` зелёный (счётчик растёт на новые тесты); данные не
  трогаются.

## Риски

- **Цикличность графа (урок 5):** обходы `setup_from`/`chain_to` обязательно `visited`-guard +
  кап длины (prerequisites/переходы плотно цикличны).
- **Тонкие цепочки у части якорей:** фолбэк на родню + минимальная длина; при нехватке —
  обычный взвешенный добор по `available`. Никогда не «поток из 1».
- **Липкий якорь (свежесть):** ротация обязательна (avoidId прошлой сессии + подмешивание
  свежести дневника), иначе тема не меняется -> «прочитал и ушёл».
- **Мёртвый раннер:** не вкладываемся в тяжёлую тайм-сессию; заголовок темы = ЧТЕНИЕ, не
  ведёный таймер. Ценность видна без запуска.
- **Пустой `preferredStyles`:** снят effective-style-фолбэком (не гейтим на онбординг).
- **Правило доверия:** тесты явно проверяют, что избранный якорь не выкидывается goal/стилем.

## Критерий готовности

- Оба генератора выдают упорядоченный якорный кластер (вход->приём->продолжения->родня) вместо
  плоского списка; заголовок темы с «почему» виден в UI.
- Стиль реально влияет у всех (effective-style-фолбэк); избранное выбирает якорь; правило
  доверия соблюдено (тесты).
- «Безопасный» режим режет критичное (фикс #2); мёртвая ветка качеств удалена (фикс #3).
- Ротация якоря работает (не тот же якорь подряд).
- Телеметрия `workout_theme` уходит; SQL-whitelist подготовлен.
- Тесты и сборка зелёные; рантайм подтверждён через DOM в обеих темах.
