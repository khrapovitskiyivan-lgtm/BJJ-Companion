## Находки

### H-1. Challenge-режим Vercel может глушить вебхук бота и крон (High, доступность)
- Где: прод, все маршруты; `/api/tg-webhook`, `/api/tg-cron`, `/api/partners`, `/api/tg-report`.
- Доказательство (curl, 2026-10-23 14:04 UTC, и с браузерным User-Agent тоже):
  ```
  POST /api/tg-webhook -> 403 mitig:challenge
  POST /api/partners   -> 403 mitig:challenge
  GET  /api/tg-cron    -> 403 mitig:challenge
  GET  /               -> 403, X-Vercel-Mitigated: challenge
  ```
- Сценарий: включён Attack Challenge Mode / правило Firewall с challenge. Браузер пользователя challenge проходит (JS), а сервер Telegram, доставляющий апдейты, нет: /start, /mute, /pause и разметка постов канала молча перестают работать. Крон Vercel, возможно, обходит challenge (не проверено).
- Не проверено: проходят ли реальные апдейты Telegram (нужен токен). Возможно, challenge срабатывает только на мой IP/клиент.
- Исправление: в Vercel -> Firewall проверить, включён ли Attack Challenge Mode; если да - выключить или добавить bypass-правило для `/api/tg-webhook` и `/api/tg-cron` (защищены секретом сами). Проверить `getWebhookInfo` (поля `last_error_message`, `pending_update_count`) - владелец делает руками с токеном.

### M-1. Токен бота в публичной истории git (Medium; High, если не отозван)
- Где: коммиты `44d64eb`, `e38057c`, файл `docs/analysis/2026-07-26-audit-legal.md` (в истории). Репо `github.com/khrapovitskiyivan-lgtm/BJJ-Companion` публичный (GET -> 200).
- Доказательство: в `git log --all -p` найден токен вида `8861636500:AAHK...`. Текущий токен в `.env.local` ДРУГОЙ (бот-id `8760713941`), то есть ротация, судя по всему, была. Валидность старого токена я не проверял (не использую утёкшие креды).
- Сценарий: если `8861636500` - живой бот (старый/тестовый), любой может слать от его имени, читать апдейты, менять webhook.
- Исправление: в BotFather для бота 8861636500 сделать /revoke (или удалить бота). Чистить историю необязательно после отзыва.

### M-2. Нет rate limiting на /api/* и анонимных RPC (Medium, злоупотребление)
- Где: `src/routes/api.partners.ts`, `api.tg-report.ts`; RPC `bjj_track`, `bjj_report_player`, `bjj_global_stats`, `bjj_channel_videos` (grant anon, `docs/sql/2026-07-17-global-stats.sql:62-63`, `2026-07-18-telemetry.sql:38`, `2026-10-23-channel-posts.sql:56`).
- Сценарий: с публичным anon-ключом из бандла любой скриптом пишет миллионы строк в `bjj_events` (whitelist событий, `detail` обрезан до 32 символов - объём на строку мал, но число строк не ограничено) и в `bjj_players` (каждый случайный uuid - новый «игрок»): глобальная статистика поясов и телеметрия засоряются, растёт размер БД (лимит 500 МБ на бесплатном Supabase).
- Исправление (после запуска): телеметрию и счётчики считать «грязными»; при аномалии - фильтр по device_id. Дёшево: в `bjj_track` отбрасывать, если от device_id > N событий за минуту (`select count(*) ... where device_id=p_device and created_at > now()-interval '1 minute'`). Для /api/* хватает текущего challenge/Firewall-правила rate limit Vercel.

### M-3. Партнёрский профиль принимает произвольные `style`, `stats`, `quota`, `device` без ограничений размера (Medium)
- Где: `src/routes/api.partners.ts:67-80`; `bjj_partner_publish` (`docs/sql/2026-08-04-partners-pause.sql:15-47`) проверяет только `belt` и `week_done`.
- Сценарий: залогиненный пользователь (своя подпись initData) пишет в `stats` jsonb мегабайты или в `style` длинный/оскорбительный текст; партнёры видят это в списке. XSS нет: React экранирует, `dangerouslySetInnerHTML` в компонентах не найден (единственный - статический init-скрипт в `src/routes/__root.tsx:127`). Затронуты только его партнёры (добавленные по коду).
- Исправление: в роуте `style` - whitelist из STYLE_ORDER, `stats` - только известные ключи с числами 0..100, `quota` - clamp 1..7; в SQL `left(p_style, 32)` и `pg_column_size(p_stats) < 2000`.

### L-1. Нет заголовков безопасности (CSP, X-Content-Type-Options, Referrer-Policy) (Low)
- Где: `vercel.json` (нет `headers`), `vite.config.ts`, `__root.tsx` - заголовков не найдено. Проверить фактические заголовки прода не смог (challenge).
- Сценарий: при появлении XSS нет второй линии защиты. Кликджекинг малозначим (нет опасных однокликовых действий).
- Исправление: добавить `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`. `frame-ancestors` НЕ ставить `'none'`: Telegram Web (web.telegram.org) открывает Mini App в iframe; если ставить - `frame-ancestors https://web.telegram.org https://*.telegram.org`. Полный CSP - после запуска, с тестом в webview iOS.

### L-2. Подбор реф-кода партнёра (Low)
- Где: `bjj_partner_accept`, код 8 hex (`upper(substring(md5(...),1,8))`), ~4.3 млрд вариантов.
- Сценарий: перебор требует валидного initData и миллионов запросов; при сотнях пользователей практически недостижим. Принятие кода сразу создаёт связь без подтверждения второй стороны - by design.
- Исправление: при росте - лимит попыток accept на tg id.

### L-3. Канал: потенциальные краевые случаи (Low)
- Где: `src/lib/channelBot.ts`.
- `msg_id` - первичный ключ без chat_id: если сменить `TG_CHANNEL_USERNAME` на другой канал, id сообщений пересекутся и перезапишут старые записи. Исправление: PK `(chat_id, msg_id)` при смене канала.
- Цикл правок: защита держится на том, что `missingTags` после дописывания пуст; плюс Telegram отвергает правку без изменений. Безопасно, если `missingTags` распознаёт собственные дописанные теги (юнит-тест на «текст + дописанные теги -> пусто» рекомендую).
- Ошибки fetch не ловятся внутри `handleChannelPost`, но внешний try/catch в вебхуке их гасит - ок.

## Что проверено и в порядке

- **Вебхук**: 503 без токена/секрета, 403 при неверном `x-telegram-bot-api-secret-token` (`api.tg-webhook.ts:229-231`). Подделать channel_post без секрета нельзя. Сравнение секрета не constant-time - для 256-битного секрета по сети несущественно.
- **Канал**: проверка `chat.username` (регистронезависимо) + Telegram шлёт channel_post только из каналов, где бот админ. Бот редактирует только сообщение из того же апдейта (`chat_id`/`message_id` из подписанного секретом апдейта) - заставить его править чужой пост без секрета вебхука нельзя. Запись в `bjj_channel_posts` - только `bjj_channel_upsert`, grant только service_role, revoke у public/anon/authenticated. RLS включён, политик нет -> прямого доступа к таблице у anon нет.
- **bjj_channel_videos**: anon только читает агрегат (id поста, число видео, дата, подпись) из публичного канала - утечки нет. `security definer` + `set search_path = public`. Подпись на клиенте выводится текстом JSX (экранируется), ссылка строится из числового id поста.
- **Отзыв anon у bjj_tg_*** (`2026-10-23-tg-revoke-anon.sql`): сигнатуры совпадают с актуальными; старые перегрузки `bjj_tg_report` (6 и 7 аргументов) были удалены `drop function` в `2026-07-22-tg-training-days.sql:12` и `2026-08-03-tg-pause.sql:12`, так что обходного пути через старую перегрузку нет. Применён ли файл в прод-БД - не проверял (нет доступа), проверочный select в конце файла владелец должен прогнать.
- **tgValidate.ts**: алгоритм HMAC корректен ("WebAppData" как ключ), constant-time сравнение, fail-closed, свежесть 24 ч с допуском -300 с. tg id в /api/partners и /api/tg-report берётся только из подписи; имя и фото - тоже из подписи. Входные поля tg-report валидируются (даты регуляркой, числа clamp).
- **Партнёрские RPC** - только service_role. Видимость: `bjj_partner_list` отдаёт профиль только связанным партнёрам (лимит 10), публичного списка нет. ПДн у партнёров: имя, фото, пояс, стиль, статы, недельный прогресс, пауза - соответствует назначению.
- **Крон**: 503 без секрета, проверка `Bearer CRON_SECRET`.
- **bjj_progress**: RLS `auth.uid() = user_id` на all.
- **Секреты в бандле**: локальная прод-сборка `.vercel/output/static` - токенов бота нет, единственный JWT имеет `"role":"anon"`, строк `SUPABASE_SERVICE_ROLE_KEY`/`CRON_SECRET`/`TELEGRAM_WEBHOOK_SECRET` нет. Прод-бандл скачать не удалось (challenge), проверялась локальная сборка от сегодня.
- **Секреты в репо**: `.env*` в .gitignore, в `git ls-files` env-файлов нет. В истории - только старый токен (M-1) и anon-ключ (публичный по природе).
- **Support.ts**: реквизиты статичны в коде (`SUPPORT.card`), подменить можно только через коммит в репо - то есть защищено доступом к GitHub/Vercel. Риск - параллельный агент (урок 6): перед деплоем сверять `support.ts` в diff.
